HW2: Phoneme Classification (Framewise Classification)
根据语音的MFCC特征，逐帧预测对应的音位（phoneme），一共41类。
一、实验记录
1. Baseline
改动：官方sample code原始配置，concat_nframes=1，1层256维，训练5轮
结果：Val Acc 0.4579
说明：只看当前帧信息量太少，成绩起点较低
2. 拼接前后帧
改动：concat_nframes从1改成11
结果：Val Acc 0.6296
说明：提升最明显的一步，前后帧提供的上下文对判断当前音位帮助很大
3. 特征标准化
改动：对输入特征做z-score标准化
结果：Val Acc 0.6295
说明：几乎没变化，可能是因为用的AdamW优化器本身自带自适应缩放，抵消了标准化的收益
4. 加深加宽模型
改动：隐藏层从1层256维改成3层512维
结果：Val Acc 0.6604
说明：模型容量变大带来实打实的提升，5轮时train/val都还在涨，没训够
5. 增加训练轮数
改动：训练轮数从5改成10
结果：Val Acc 0.6776
说明：确实还有空间，但train/val差距也略微拉大
6. 加入Dropout
改动：每层加dropout，rate=0.25
结果：Val Acc 0.6760
说明：最终准确率没提升，但train acc明显被压低，train/val差距由正转负，说明确实在抑制过拟合，只是同样轮数下学习效率变慢了
7. 组合调整
改动：concat_nframes改成21，dropout降到0.15，训练轮数改成20
结果：Val Acc 0.7302
说明：一次改了多个变量，没法拆分单独贡献，但train/val差距很小，训练健康
8. 加入BatchNorm
改动：每层加BatchNorm，因显存不够concat_nframes降到17，训练轮数改成30
结果：Val Acc 0.7344
说明：提升幅度已经很小，接近这套配置的上限，train/val基本重合，没有过拟合
二、结论
拼接前后帧收益最大，说明这类任务光靠单帧信息不够，上下文窗口是最值得优先调的参数。
标准化效果好不好要看优化器，AdamW自带自适应缩放时，标准化的边际收益会被削弱。
Dropout的效果不一定体现在最终准确率上，看train/val差距更能判断它有没有起作用，加了之后往往需要更长训练时间才能把准确率补回来。
后期几组实验为了效率做了组合调整，没有严格控制单一变量，成绩更好但说不清具体是哪一步贡献的，这是这次实验不够严谨的地方。
拉大前后帧拼接时，显存限制迫使参数往回调，说明实际调参也要在效果和硬件资源之间做平衡。
整个过程train/val差距始终不大，说明模型复杂度和正则化手段搭配得比较合适，没有出现明显过拟合。
